## 1. Роль і завдання

Ти виступаєш як Senior Desktop Application Engineer.

Твоє завдання — спроєктувати та створити технічний фундамент нового настільного браузера з нестандартною системою керування вебсторінками.

Це не звичайний браузер із горизонтальним рядом вкладок.

Основна концепція проєкту — **Spatial Browser / Desktop Workspace**.

Замість традиційної системи вкладок кожна відкрита вебсторінка є окремим незалежним вікном, яке користувач може вільно переміщувати, масштабувати та накладати одне на одне в межах спільного робочого простору.

Водночас браузер повинен мати звичні елементи навігації:
- Стартову сторінку з візуальними закладками.
- Адресний рядок.
- Менеджер відкритих вкладок.
- Панель керування робочим простором.

Мета першого етапу — створити працездатний прототип із повноцінною базовою навігацією та основною Spatial-функціональністю.

## 2. Технологічний стек

Використовуй:

- Electron — десктопна оболонка.
- Chromium — браузерний рушій через Electron.
- WebContentsView — для відображення незалежних вебсторінок.
- HTML / CSS / JavaScript — інтерфейс користувача.
- Node.js — системна логіка.
- JSON — початковий формат збереження конфігурації, закладок і параметрів робочого простору.

Використовуй актуальні стабільні версії сумісних залежностей.

Не використовуй iframe як основний механізм відображення вебсторінок.

Не використовуй застарілий Electron BrowserView.

Для вебконтенту використовуй WebContentsView.

## 3. Концепція інтерфейсу

Інтерфейс повинен складатися з чотирьох функціональних компонентів.

### A. Верхня панель навігації

Містить:

- Поле введення URL.
- Пошук через пошукову систему, якщо введений текст не є URL.
- Кнопку переходу.
- Кнопку створення нового вебвікна.
- Кнопку відкриття списку вкладок.
- Кнопку відкриття Home Hub.

Панель повинна бути компактною та мінімалістичною.

Не копіюй інтерфейс Chrome або Edge. Створи власну візуальну мову, яка відповідає концепції Spatial Browser.

### B. Spatial Workspace

Це основна частина програми.

Вимоги:

- Робочий простір займає максимальну доступну площу вікна.
- Кожна вебсторінка відображається в окремому WebContentsView.
- Кожна сторінка має власну візуальну рамку та заголовок.
- Вікна можна переміщувати мишкою.
- Вікна можна масштабувати за краї та кути.
- Вікна можуть перекривати одне одного.
- Активне вікно повинно переходити на передній план.
- Кожне вікно має кнопку закриття.
- Кожне вікно має власні кнопки навігації назад і вперед.
- Вікна не повинні виходити за межі доступної робочої області.
- Зміна розмірів головного вікна повинна коректно оновлювати координати вебвікон.

Важливо: координати та розміри вікон повинні контролюватися головним процесом Electron через bounds відповідних WebContentsView.

Не намагайся просто розмістити WebContentsView у DOM. Вони керуються через Electron Main Process, тому необхідно реалізувати окремий механізм синхронізації координат між інтерфейсом і головним процесом.

Передбач правильне врахування розмірів верхньої панелі та інших елементів інтерфейсу.

### C. Home Hub — стартова сторінка із закладками

Створи окрему стартову сторінку, концептуально схожу на систему Speed Dial в Opera GX.

Це не звичайна вебсторінка, а вбудований компонент браузера.

Основне призначення — швидкий доступ до часто використовуваних сайтів.

**Візуальна концепція:**
- Сітка візуальних закладок.
- Картки сайтів із назвою та іконкою або прев'ю.
- Можливість додавати нові закладки.
- Можливість видаляти та редагувати закладки.
- Можливість змінювати порядок розташування.
- Клік по закладці відкриває відповідний сайт у Spatial Workspace.

**Механізм відображення:**

Home Hub повинен відкриватися як висувна шторка або окрема стартова область робочого простору.

Вимоги:
- Hub можна відкрити через кнопку у верхній панелі.
- Hub можна приховати тією ж кнопкою або відповідною дією.
- У прихованому стані він не повинен займати постійний простір робочої області.
- Відкриття Hub не повинно знищувати або перезавантажувати вже відкриті вебвікна.
- Стан і розташування відкритих вебвікон повинні зберігатися після приховування Hub.
- Повторне відкриття повинно відновлювати попередній стан робочого простору.

Передбач можливість використання Hub як початкового екрана браузера, коли ще немає відкритих вебвікон.

**Зберігання даних:**

На першому етапі достатньо локального JSON-файлу.

Зберігай:
- Назву закладки.
- URL.
- Іконку або шлях до локального зображення.
- Порядок відображення.

Не реалізовуй синхронізацію закладок між пристроями.

### D. Tab Manager — список відкритих вебвікон

Оскільки браузер використовує просторову систему вкладок, необхідно передбачити альтернативний спосіб швидкого перемикання між відкритими сторінками.

Створи окрему кнопку у верхній панелі, яка відкриває спливаюче меню зі списком усіх відкритих вебвікон.

**Вміст меню:**
- Назва вебсторінки.
- Іконка сайту, якщо доступна.
- URL або скорочений URL.
- Позначення активного вікна.
- Кнопка закриття відповідного вікна.

**Поведінка:**
- Натискання кнопки відкриває компактне спливаюче меню.
- Меню відображає актуальний список усіх відкритих WebContentsView.
- Натискання на елемент активує відповідне вікно та переносить його на передній план.
- Після вибору вікна меню автоматично закривається.
- Закриття вебвікна повинно автоматично оновлювати список.
- Нові вебвікна повинні автоматично з'являтися у списку.
- Активне вікно повинно мати візуальне виділення.

Меню не повинно постійно займати простір інтерфейсу.

Воно має відкриватися поверх робочої області та закриватися після вибору елемента або кліку поза його межами.

**Важливо:** Tab Manager є лише альтернативним способом навігації. Він не повинен замінювати або обмежувати просторову систему розташування вебвікон.

## 4. Архітектура безпеки

Обов'язково дотримуйся рекомендацій Electron Security:

- nodeIntegration: false.
- contextIsolation: true.
- sandbox: true, де це сумісно з реалізацією.
- preload.js для безпечного мосту між процесами.
- IPC із чітко визначеним переліком дозволених операцій.
- Не відкривай Node.js API для завантажених вебсторінок.
- Не довіряй URL або повідомленням із вебконтенту.

Не використовуй небезпечні універсальні IPC-обробники, які дозволяють довільне виконання команд.

Локальний інтерфейс браузера та завантажені вебсторінки повинні мати чітко розділені контексти безпеки.

## 6. Основні технічні вимоги

Особливу увагу приділи:

1. Синхронізації DOM-рамок вебвікон із реальними WebContentsView.
2. Правильному управлінню Z-index і порядком перекриття.
3. Обробці зміни розміру головного вікна.
4. Обмеженню переміщення вебвікон межами робочої області.
5. Обробці закриття WebContentsView та очищенню ресурсів.
6. Коректній роботі декількох незалежних вебсторінок.
7. Обробці некоректних URL та помилок навігації.
8. Синхронізації Tab Manager зі станом відкритих вебвікон.
9. Збереженню та завантаженню закладок.
10. Коректному відображенню Home Hub поверх або замість робочого простору.
11. Взаємодії DOM-елементів інтерфейсу з нативним шаром WebContentsView.

**Особливо важливе обмеження Electron:**

WebContentsView не є звичайними HTML-елементами. Вони відображаються окремим нативним шаром, тому звичайне CSS-перекриття між DOM та WebContentsView не працює так, як між звичайними елементами DOM.

Це стосується також:
- Home Hub.
- Спливаючого меню Tab Manager.
- Елементів керування вебвікнами.

Спроєктуй взаємодію з урахуванням цього обмеження.

Не допускай ситуації, коли WebContentsView перекриває кнопки, меню або інші елементи інтерфейсу.

Якщо для цього необхідно змінювати bounds, порядок відображення або тимчасово приховувати вебвікна, реалізуй це централізовано через Main Process.

Не використовуй CSS z-index як єдиний механізм керування шарами.

Перший прототип вважається успішним, якщо:

- Є верхній адресний рядок.

- Можна видаляти закладки.
- Перехід за закладкою відкриває відповідний сайт.

## 11. Головний пріоритет проєкту

**Spatial Browser — це браузер, побудований навколо просторової організації вебконтенту, а не традиційної системи вкладок.**

Основою залишається система вільно розташованих незалежних вебвікон.

Home Hub забезпечує швидкий доступ до сайтів і виступає стартовою точкою навігації.

Tab Manager забезпечує швидке перемикання між відкритими вебвікнами, не порушуючи просторової концепції.

Усі три компоненти повинні працювати як єдина система.

Головний пріоритет — **працездатний браузер із реальною вебфункціональністю, а не красива демонстрація інтерфейсу без функціональної основи.**
